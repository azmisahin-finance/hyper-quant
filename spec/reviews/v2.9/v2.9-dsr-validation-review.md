# HYPER-QUANT v2.9 — DSR Validation Review

Status: REVIEW_REQUIRED

## Decision

No new normative specification version is required. The v2.9 research contract can accommodate a computed Deflated Sharpe Ratio (DSR) and search diagnostics as implementation controls.

## Research basis

The DSR was introduced to correct performance inflation from non-normal returns and selection bias under multiple testing. Bailey and López de Prado describe DSR as a search-adjusted Sharpe inference tool. The implementation in this repository is explicitly labeled a classic DSR-LS approximation and must not be represented as a guarantee of future profitability.

## Implemented controls

- `src/research/dsr.ts`: computes Sharpe, skewness, kurtosis, finite-sample Sharpe uncertainty, expected maximum Sharpe under the committed trial count, and DSR.
- `src/research/search-diagnostics.ts`: binds selected candidate returns, committed trial count, CSCV/PBO, computed DSR and an evidence hash.
- adversarial tests reject non-finite/zero-variance inputs and verify that increasing committed trial count cannot improve the DSR benchmark.

## Residual risk

The committed trial count is durable, but the full campaign-level orchestration is still limited. Exact production research conventions for return periodicity, dependence, and parameter search breadth must be fixed before promotion-grade use.
