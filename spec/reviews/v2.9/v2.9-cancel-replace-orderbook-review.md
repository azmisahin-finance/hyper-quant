# HYPER-QUANT v2.9 — Cancel/Replace + Order-Book Execution Review

**Status:** REVIEW_REQUIRED

## Scope
This vertical slice hardens non-live execution realism. It does not grant live mutation authority.

## Controls added
- Deterministic L2 order-book state with monotonic sequence/time enforcement.
- Crossed-book rejection, duplicate price rejection, and visible-level cancellation bounds.
- Deterministic queue-ahead estimation and queue-consumption fill model.
- Two-phase cancel/replace: request/cancel-pending, then replacement only after the pending request is still trusted.
- Replacement quantity defaults to the then-current remaining quantity, so late fills during cancel latency cannot create synthetic over-ordering.
- Replacement request replay, context tampering, invalid quantity/price, and terminal-order reuse fail closed.

## Adversarial evidence
- replayed or rewound book snapshots rejected;
- crossed snapshots rejected;
- queue position changes only through explicit displayed cancellations/trades;
- late fill during cancel/replace reduces replacement quantity;
- replacement cannot enlarge beyond current remaining quantity;
- request identity is non-replayable and context-bound;
- resting orders wait for visible queue consumption before receiving fills.

## Residual obligations
This slice is not a production matching engine. The following remain open before paper/live use:
- venue-calibrated queue-position estimation,
- order-book event semantics/checkpointing per venue,
- latency distribution calibration,
- market-impact calibration,
- venue-specific cancel/replace semantics,
- live remote reconciliation under cancellation races.
