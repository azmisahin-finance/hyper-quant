## Executive finding

v2.7 was not sufficiently implementation-aligned to claim closure of its execution-safety gaps. The re-review found concrete mismatches in GAP-08: kill applicability was not scope-aware, the authorization hash was absent, expiry was checked using a stale caller-supplied clock value after asynchronous barriers, and hard-risk/dependency/execution-policy controls were not executable predicates.

A v2.8 hardening amendment is therefore required and has been applied. The repository now contains executable primitives for canonical intent transitions, durable append-only intent logging, bounded reconciliation semantics, scope-aware kill applicability, hashed authorization snapshots, fresh-time validation, and deterministic adversarial tests for these controls.

This closes the **repository-level execution-safety alignment findings only**. It does not close the remaining research-plane, capital-plane, statistical-validation, holdout, artifact-identity, portfolio-risk, signer, venue-adapter, or live reconciliation implementation obligations.

## New findings resolved in v2.8

### EXEC-EXP-01 — stale-clock expiry validation

**Severity:** P1
**Finding:** v2.7 reused the initial `now` value after asynchronous barriers. An authorization could outlive its declared 5-second deadline but still be accepted.
**Remediation:** validation now calls an authoritative clock for every validation point. The adversarial suite advances a deterministic test clock across the commit barrier and requires `EXPIRED_AUTHORIZATION` with zero remote mutations.

### EXEC-SCOPE-01 — unscoped kill activation

**Severity:** P1
**Finding:** v2.7 stored kill type without a target scope. A venue kill could affect unrelated venues.
**Remediation:** kill activations now carry explicit applicability records, and the predicate checks exact venue/strategy and cross-cutting dependency/model/research identifiers on every attempt.

### EXEC-HASH-01 — missing authorization-hash binding

**Severity:** P1
**Finding:** v2.7 documented `authorization_hash` but the implementation did not carry or verify one.
**Remediation:** v2.8 computes a canonical SHA-256 authorization hash over target, versions, deadline, and nonce and rejects tampering before handoff.

### EXEC-GATE-01 — safety predicates were implicit

**Severity:** P1
**Finding:** v2.7 had no executable hard-risk, dependency-compatibility, or execution-policy evaluator.
**Remediation:** v2.8 makes these explicit fail-closed evaluator contracts; authorization cannot be created or consumed unless all three pass.
