## GAP-08 proof currently present

The executable scaffold verifies four critical cases:

1. `VENUE_KILL` raised before final revalidation yields `DENIED / STALE_AUTHORIZATION` and zero remote mutation attempts.
2. A dependency-graph version race before commit boundary yields denial with zero remote mutation attempts.
3. A consumed authorization snapshot cannot be replayed.
4. A kill after commit boundary produces `IN_FLIGHT`, preserves the fact that a remote handoff occurred, and leaves the mutation pending reconciliation.

These tests use `DeterministicBarrier` only as a scheduler. The safety decision remains in production `MutationCoordinator` code. The test mutation executor is also test-only.

## Important limitation

The scaffold does not claim distributed atomicity between local authorization and a real external venue. The commit boundary is a local handoff boundary. Once a remote submission can be in flight, the only sound resolution is venue reconciliation. Real venue adapters, durable storage, signing boundaries, and production network policy remain future verification work.
