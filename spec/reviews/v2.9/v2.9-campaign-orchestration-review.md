# HYPER-QUANT v2.9 Campaign Orchestration Review

**Status:** IMPLEMENTED / REVIEW_REQUIRED
**Scope:** non-live research search-campaign orchestration
**Decision:** no normative specification version change; continue under v2.9

## Findings and controls

| ID | Finding | Severity | Control | Verification |
|---|---|---|---|---|
| CAMP-01 | Candidate work could be executed without durable pre-registration | P1 | ResearchCampaignRunner registers every candidate before compute | Adversarial integration test |
| CAMP-02 | Analyst-supplied trial count could understate multiple testing | P1 | Committed trial count is derived from ResearchTrialLedger | Adversarial integration test |
| CAMP-03 | Candidate selection could be changed after diagnostics | P1 | Deterministic mean-return selection with lexicographic tie break; campaign final record binds selected candidate and evidence hash | Adversarial integration test |
| CAMP-04 | Campaign evidence could be lost after process completion | P1 | Append-only campaign ledger with fsync and final evidence hash | Integration test |
| CAMP-05 | Holdout could be consumed before candidate selection | P1 | Campaign search phase explicitly excludes holdout; holdout remains a separate post-selection boundary | Contract documentation + code structure |
| CAMP-06 | Concurrent campaign writers could race the campaign ledger | P1 | Campaign ledger serializes start/candidate/final writes through a single write queue | Regression test coverage |
| CAMP-07 | Candidate crash could produce false completed campaign | P1 | Crash is durably recorded as CRASHED and no CAMPAIGN_FINAL is written | Adversarial integration test |

## Residual obligations

The orchestrator is non-live. It does not grant promotion authority, does not observe raw holdout data during search, and does not replace independent economic validation. A later phase must connect selected candidates to controlled holdout evaluation and the existing promotion evidence gate.
